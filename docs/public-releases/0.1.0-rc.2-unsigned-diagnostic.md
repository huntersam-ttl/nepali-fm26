# Nepal Football Simulation 0.1.0-rc.2 unsigned diagnostic

This candidate validates the universal macOS packaging path. It is an unsigned diagnostic artifact, not a public-ready release.

## Build result

- Main Tauri executable: universal `x86_64 + arm64`.
- Bundled Node sidecar: universal `x86_64 + arm64`.
- No other native Mach-O binaries are currently bundled.
- Actual executable/runtime minimum: macOS 11.0. The previous `10.13` setting was too low and is now explicit at `11.0`.
- Tauri hardened runtime is explicitly enabled. No custom entitlements are configured; spawning the bundled Node process, loopback IPC, app-data saves, and built-in `node:sqlite` did not prove a special entitlement necessary.
- The configured 1024px PNG is used as the macOS bundle icon; Tauri generates the platform icon assets during packaging.

## Future signing order

Sign nested `.dylib`, `.framework`, `.node`, and helper executables first; sign the universal Node sidecar; sign `Contents/MacOS/nepal-football-sim`; verify the app; create the DMG; submit the DMG to notarization; staple only after `Accepted`.

## Apple credential checklist

The signing machine must have an active Apple Developer Program membership, a Developer ID Application certificate with its matching private key in Keychain, the Team ID, and a notarization keychain profile. Configure the profile locally with `xcrun notarytool store-credentials <profile> ...`; never commit credentials. The release script verifies `DEVELOPER_ID_APPLICATION` against `security find-identity` and uses `NOTARY_PROFILE` only as a keychain-profile name.

`scripts/build-macos-release.sh --signed` fails before building if the signing identity is absent. `--notarize` additionally requires `NOTARY_PROFILE` and fetches a rejection log when submission fails.

The bundle identifier remains `com.local.nepal-football-simulation` for `0.1.0`; changing it requires a save migration plan because macOS app-data discovery may change.
